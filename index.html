Common Errors

❌ Failed to connect
Double-check your Client ID and Client Secret for typos. Re-run claude mcp remove mulesoft then re-add with corrected values.
🚫 403 Forbidden on operations
Your Connected App is missing scopes. Go to Access Management → Connected Apps, edit the app, and add the missing scope group. No need to regenerate credentials — just add the scope and save.
⚠️ npx: command not found
Node.js is not installed or not on your PATH. Install with brew install node (macOS) or download from nodejs.org. After installing, close and reopen your terminal.
🔧 Java/Maven errors when building
Building Mule projects requires Java 17 and Maven. Install with: brew install openjdk@17 maven. Then: export JAVA_HOME=$(/usr/libexec/java_home -v 17). Add that line to your ~/.zshrc.
🌐 EU region — wrong endpoint
If your Anypoint org is in the EU, set ANYPOINT_REGION=PROD_EU. Remove and re-add: claude mcp remove mulesoft then re-run the add command with PROD_EU.
🔑 ANYPOINT_CLIENT_ID must be set
The MCP server is connected but has no credentials. Remove and re-add with env vars: claude mcp remove mulesoft then re-add with -e ANYPOINT_CLIENT_ID=... -e ANYPOINT_CLIENT_SECRET=....
📦 Maven deployment fails — settings.xml missing
Maven needs ~/.m2/settings.xml with your Anypoint credentials. See the Maven Setup section below. Use the ~~~Client~~~ username format with CLIENT_ID~?~CLIENT_SECRET as the password.
⚠️ Deploy fails but MCP tools work
The MCP server and Maven use different credential paths. MCP reads env vars; Maven reads ~/.m2/settings.xml. Both need to be configured. Also check vCore availability in Runtime Manager → Usage.
📦 Maven Setup — only needed for CloudHub deployment (optional, ~20 min)

To deploy Mule apps to CloudHub, Maven needs your Anypoint credentials. One-time setup.

What is Maven?

Maven is the build tool that compiles your Mule project and uploads it to CloudHub. Think of it like a shipping company — it packages your integration code and delivers it to the cloud. Without Maven credentials, your code builds but can't be delivered.

1

Store credentials in macOS Keychain

security add-generic-password -s "ANYPOINT_CLIENT_ID" -a "$USER" -w "paste_your_client_id" security add-generic-password -s "ANYPOINT_CLIENT_SECRET" -a "$USER" -w "paste_your_client_secret"
2

Create the Maven settings file

mkdir -p ~/.m2 && \ CLIENT_ID=$(security find-generic-password -s "ANYPOINT_CLIENT_ID" -w) && \ CLIENT_SECRET=$(security find-generic-password -s "ANYPOINT_CLIENT_SECRET" -w) && \ cat > ~/.m2/settings.xml << EOF <?xml version="1.0" encoding="UTF-8"?> <settings> <servers> <server> <id>anypoint-exchange-v3</id> <username>~~~Client~~~</username> <password>\${CLIENT_ID}~?~\${CLIENT_SECRET}</password> </server> </servers> </settings> EOF
What's ~~~Client~~~? Anypoint's format for Connected App credentials. The CLIENT_ID~?~CLIENT_SECRET password pattern is specific to MuleSoft's Maven plugin.
3

Verify it works

security find-generic-password -s "ANYPOINT_CLIENT_ID" -w # Should print your Client ID
🔧 Maven cached failure — *.lastUpdated files
If Maven tried to download a dependency and failed, it creates .lastUpdated marker files. Fix: find ~/.m2/repository -name "*.lastUpdated" -delete. Safe — only removes failure markers.

Best Practices

Get the most out of MuleSoft + Claude Code with these guidelines.

🔒 Security

  • Rotate credentials quarterly. Delete and re-create the Connected App every 90 days.
  • Use minimum scopes for production. Start broad during exploration, then tighten to only what you need.
  • Use --scope local for shared machines. Restricts credentials to the current project directory.
  • Never commit credentials. The MCP config lives in ~/.claude/, not your project repo.

📦 Exchange-First Development

  • Search before you build. Ask Claude to search Exchange before writing any integration code. There are thousands of pre-built assets.
  • Start from accelerators. Industry accelerators contain production-grade assets that would take weeks to build from scratch.
  • Publish back to Exchange. If you build something reusable, publish it to your org's Exchange.

🚀 Deployment

  • Start in Sandbox, promote to Production. Always deploy to Sandbox first. Verify it works, then redeploy to Production.
  • Use Micro workers for development. 0.1 vCore (Micro) workers are sufficient for development and testing.
  • Version your API specs. Make sure your spec has a proper semantic version before publishing to Exchange.

🤖 Working with Claude Code

  • Be specific with prompts. "Add an HTTP listener on port 8081 with path /api/v1/patients" works better than "add a listener."
  • Chain operations naturally. Claude handles multi-step requests: "Create a project, add a flow, then deploy to Sandbox."
  • Review generated flows. Always review the generated Mule XML before deploying, especially for production.

🔧 Troubleshooting

  • Check connection first. Run claude mcp list to verify the server is connected.
  • Re-add if stuck. claude mcp remove mulesoft then re-add clears cached state.
  • Check vCore availability. Deployments fail if your org has no available vCores. Check Runtime Manager → Usage.

🏢 Large Anypoint Orgs — What to Expect

  • Business Group scoping matters. In orgs with multiple Business Groups, Claude only sees assets and applications in the groups covered by your Connected App's scopes. If a search returns nothing, check which group you're scoped to.
  • Exchange search returns top matches, not all results. Large orgs with hundreds of assets will see curated top hits. Refine with specific terms: "FHIR R4 patient" beats "FHIR."
  • Use --scope local on shared dev machines. If multiple developers share a machine or a CI environment, --scope local keeps each project's credentials isolated from the others.
  • API Manager policies require the right environment. Policies on a Production API instance require your Connected App to have Production-scoped permissions — not just Sandbox.

Glossary

Plain English explanations for terms you'll encounter.

Connected App

A username and password for programs (not people) to access Anypoint Platform. Instead of typing your email and password, programs use a Client ID and Client Secret. Think of it like a key card for software.

Scopes

Permissions that control what a Connected App can do. Like giving a house key that only opens certain rooms. "Exchange Viewer" lets it browse assets. "Runtime Manager Write" lets it deploy apps.

Maven

A build tool that compiles your Mule project and uploads it to CloudHub. Think of it as a shipping service — it packages your code and delivers it to the cloud. You configure it once in ~/.m2/settings.xml.

vCores

Computing power in CloudHub, measured in virtual CPU cores. A Micro worker (0.1 vCores) is enough for development. If you're out of vCores, deployments will fail.

CloudHub 2.0

MuleSoft's cloud hosting service where your Mule apps run. Sandbox is for testing; Production is for real traffic.

Exchange

MuleSoft's app store for integration assets — pre-built connectors, API templates, code libraries, and complete accelerators. Always search Exchange before building from scratch.

MCP (Model Context Protocol)

A standard that lets AI assistants like Claude use tools. The MuleSoft MCP Server gives Claude the ability to search Exchange, deploy apps, and manage APIs — all through natural language.

FHIR R4

A healthcare data standard for exchanging medical records. R4 is the current version used by most hospitals and required by US regulations for patient data access.

Troubleshooting

🔴 Red dot or server not showing in Tools & MCPs

Check that ~/.cursor/mcp.json exists and is valid JSON. Common issues:

  • Missing comma between fields
  • Extra quote or missing quote around credentials
  • File saved in the wrong location (must be ~/.cursor/mcp.json, not ~/.cursor/mcp.json.txt)

Validate the JSON: cat ~/.cursor/mcp.json | python3 -m json.tool — must print without errors.

⚠️ npx: command not found
Node.js is not installed or not on your PATH. Install with brew install node (macOS). After installing, restart Cursor completely.
🚫 403 Forbidden on operations
Your Connected App is missing scopes. Go to Anypoint → Access Management → Connected Apps, edit the app, and add the missing scope group. No need to regenerate credentials.
⚠️ OAuth redirect fails (cursor:// protocol error)

This is a known bug when using the Anypoint Code Builder VS Code extension inside Cursor. The browser tries to redirect via the cursor:// protocol, which fails and times out after 5 minutes.

Solution: Use the MCP server approach (this guide) instead of the OAuth extension approach. The MCP server uses client credentials and does not require a browser redirect. You do not need the Anypoint Code Builder extension.

Tips & Gotchas

What experienced developers have learned using Cursor with enterprise integration platforms.

🧠 Context Window Management

  • Avoid @codebase for complex Mule tasks. It uses summarization that can miss critical details in large projects. Explicitly reference files with @ instead.
  • Keep Mule XML files under 500 lines. Cursor's agent defaults to reading the first 250 lines. Split large flows into focused files.
  • Start a new conversation after completing a feature. Old context can pollute new tasks — fresh conversations give cleaner results.

📋 Rules Files (.cursorrules)

Cursor uses .cursorrules files (similar to CLAUDE.md) to enforce project conventions. For MuleSoft projects, add these rules to prevent the AI from generating non-compliant XML:

  • Global elements in global.xml only. All shared HTTP, DB, and security configs must go in global.xml.
  • No hardcoded environment properties. Always reference via ${env}-properties.yaml.
  • YAML strict typing. Port values must be strings: port: "8081" not port: 8081.
  • Connector version verification. Tell Cursor to check the MuleSoft Maven repo before suggesting connector versions — prevents hallucinated version numbers.
  • Never commit credentials. Explicit rule to keep secrets out of tracked files.

🤖 Agent Mode Boundaries

  • One file at a time for complex changes. Broad commands like "refactor the whole integration" often cause the agent to modify too many files and break builds.
  • Disable "YOLO mode" (auto-run). Always require human approval for shell commands. Auto-run can execute destructive operations without confirmation.
  • Verify generated Mule XML before deploying. Cursor excels at tactical code but can miss architectural constraints. Review before any CloudHub deploy.
  • Don't expose all 18 tools by default. If you only need Exchange search, restrict toolsets in your MCP config to keep the agent's context focused.

🏢 Enterprise Considerations

  • Route Cursor traffic through an AI Gateway. For team deployments, use a gateway (like Portkey) to centralize API keys, enforce token budgets, and prevent PII leakage in prompts.
  • Multi-repo environments degrade Cursor. Cursor struggles at scale with 50+ repositories. For large enterprise setups, scope each Cursor session to one integration project.
  • Salesforce governor limits apply. If using Cursor for Salesforce + MuleSoft work, AI-generated SOQL and DML may work in isolation but fail with 200+ records. Manually review for bulkification.

The Error Recovery Pattern — What Replaces the Manual Fix

When a Salesforce push fails, Mule's built-in Error Handler scope catches the fault, logs it with full context, and can re-attempt with corrected values — all within the same flow. Recoverable errors are retried automatically; unrecoverable records land in a structured error log for human review. Significantly reduces unplanned on-call incidents for recoverable failure classes.

Note: error handler scopes and retry logic require explicit flow configuration. Anypoint MQ dead-letter queuing requires an Anypoint MQ subscription.

What Headless 360 Is

Headless 360 is not a product SKU — it's an architectural framework. It describes the complete decoupling of Salesforce platform capabilities from the Lightning browser UI, exposing everything through APIs, MCP tools, and CLI commands so AI agents can operate Salesforce without a human ever opening a browser.

In Era 3.0, the UI becomes an optional "ephemeral artifact" rendered on demand. Salesforce becomes a programmable substrate — a "building with loading docks on every side" — rather than a lobby humans must walk through.

The Four-Tier Architecture

Headless 360 opens the Salesforce ecosystem through four operational tiers, with MuleSoft governing the connections between them.

Tier 1 — System of Engagement

User-facing interfaces and external AI tools: Claude Code, Cursor, GitHub Copilot, Slack, ChatGPT, and any custom frontend. This is where your AI editor lives.

Tier 2 — System of Agency

MCP providers and management modules: mcp-provider-core, mcp-provider-lwc-experts, mcp-provider-apex, mcp-provider-testing, mcp-provider-devops. This tier manages what tools are exposed to agents.

Tier 3 — System of Work

Operational actions and database mutations: sobject-mutations, soql_query, invocable_actions, sobject-user-context. This is where agents actually read and write Salesforce records.

Tier 4 — System of Context

Foundational metadata and analytics: data-cloud-queries, tableau-next, salesforce-api-context, mcp-provider-metadata. The data layer that grounds agent reasoning.

Where MuleSoft Sits

Salesforce natively owns localized CRM agency — workflows, sharing rules, per-user OAuth, and reasoning within the Customer 360 stack.

MuleSoft owns the enterprise-wide control plane — multi-agent orchestration, cross-platform routing, and integration governance across the entire hybrid IT landscape.

MuleSoft Omni Gateway sits inline between autonomous agents and MCP servers, governing all Agent-to-Agent (A2A) and MCP traffic: PII/PHI detection and redaction, rate limiting, ABAC enforcement, and schema validation.

The integration layer as MCP wrapper: MuleSoft abstracts backend complexity by wrapping existing System APIs and Process APIs directly into MCP tools. Through zero-code configuration, it translates standard REST APIs into MCP wrappers — making legacy databases and external systems dynamically discoverable by Salesforce agents without new custom code.

Connect Your AI Editor to Salesforce

Two paths: a cloud-hosted Salesforce MCP Server (recommended for teams), or a local Salesforce DX MCP Server (recommended for individual developers).

☁️

Hosted MCP Server

Configured in Salesforce Setup. Enforces org-level sharing rules. Best for teams and production use.

💻

Salesforce DX MCP Server

Runs locally via npm. Uses your CLI-authenticated org. Best for individual developers and sandbox work.

Path A — Hosted MCP Server

1

Activate the MCP Server in Salesforce Setup

Log into Salesforce → Setup → MCP Servers. Select a standard template (e.g., salesforce-api-context) and click Activate. For custom servers, go to Integration → Salesforce MCP Servers.

2

Create an External Client App

In Setup, create a new External Client App (ECA). Legacy Connected Apps are not supported for MCP agentic handshakes.

Important: Use External Client App Manager, not Connected Apps. The modern OAuth security model for agents requires ECA.
3

Configure OAuth

Enable OAuth on the ECA. Set the Callback URL to match your client (Claude, Cursor, or Postman for testing). Assign required scopes: mcp_api and refresh_token. Enforce JWT-based access tokens and PKCE.

Security: An over-scoped agent could execute anything a System Administrator could. Restrict scopes to only what the agent needs. Never use full scope for an agent.
4

Add to Cursor or Claude Code

Copy the Consumer Key from the ECA and add it to your editor's MCP config:

Cursor — mcp.json configuration
{ "mcpServers": { "salesforce": { "command": "npx", "args": [ "-y", "@salesforce/mcp", "--orgs", "your_org_username_or_alias", "--toolsets", "core,metadata" ] } } }
--toolsets: Don't enable all 60+ tools at once — it overwhelms the agent's context. Use core to start, then add metadata, devops, or lwc-experts as needed.
Claude Code — terminal command
claude mcp add salesforce \ --scope user \ -- npx -y @salesforce/mcp \ --orgs your_org_username_or_alias \ --toolsets core,metadata

Path B — Salesforce DX MCP Server (Local)

1

Prerequisites

Node.js 18+ and the Salesforce CLI must be installed:

npm install -g @salesforce/cli sf --version # Should print 2.x or higher
2

Authorize your Salesforce org

sf org login web --alias my-sandbox # Browser opens — sign in to your Salesforce org sf org list # Verify it appears
3

Verify the connection in your editor

After adding the config, open Agent mode (Cursor: ⌘N) or a Claude Code session and try:

List my Salesforce org's accounts where Type = 'Customer' limit 10
✅
What success looks like

The agent returns a list of Account records from your org. If you see Salesforce data, you're fully connected.

Troubleshooting

⚠️ cursor:// OAuth redirect fails (5-minute timeout)
This is a known issue with the Salesforce browser-redirect OAuth flow inside Cursor. Use the Salesforce DX MCP Server (Path B) instead — it authenticates via CLI without a browser redirect. The DX server uses your locally-authorized org credentials, bypassing the protocol issue entirely.
🚫 "INSUFFICIENT_ACCESS" errors
The user account you authorized doesn't have permissions for the object or action. Check profile-level object permissions in Salesforce Setup. For sandbox work, use a System Admin profile. For production, scope permissions to exactly what the agent needs.
⚠️ Too many tools — agent context overloaded
Don't use --toolsets all. The Salesforce MCP server exposes 60+ tools and all of them loaded simultaneously overwhelm the agent's context window. Start with --toolsets core and add specific toolsets only when you need them.

Problem: Severe administrative burden — manual form processing and clerical paperwork delayed patient treatments and caused staff burnout.

Solution: Autonomous agents handle patient onboarding, intake form processing, and longitudinal record updates using Document AI. Clinicians focus entirely on patients.

Data: Agents read unstructured clinical data from intake forms, write to longitudinal patient records, and trigger follow-up tasks — all without staff logging into Salesforce.

Compliance: Agentforce Trust Layer automatically detects and masks PHI/PII before it reaches the LLM. HIPAA adherence built in.

Result: $1.5 million in savings. 459% ROI.

🏨 Hospital Operations — Capacity Command Center (UChicago Medicine, RUSH)

Problem: Managing complex clinical capacity bottlenecks and tracking regional disease outbreaks.

Solution: Hospital Operations Agent acts as an autonomous command center — predicts inpatient/outpatient surges, tracks inventory, manages bed and staff allocation. Epidemiology Agent automates lab intake, deduplicates cases, and generates outbreak response plans.

Data: Reads real-time hospital inventory, clinical capacity data, lab intake results, medical imaging (Viz.ai), and wearable metrics (Verily).

Compliance: Zero Copy integration via Data Cloud — agents read massive health data without physically moving it out of secure storage. Strict role-based permissions govern data visibility.

💊 Healthcare Payers — Claims & Coverage Automation

Problem: High-volume member service operations — deductible questions, prior auth, billing status, out-of-pocket estimates.

Solution: Claims & Coverage Agent provides always-on self-service resolution. Reads benefit plans, provider networks, and claims systems. Writes grievance logs, auth requests, and builds a "Member 360" profile.

Compliance: HL7 FHIR-aligned APIs. Voice interactions use HIPAA-ready Agentforce Voice.

🔗 EHR Interoperability via MuleSoft (General Care Coordination)

Problem: Care gaps from disconnected referral workflows, manual medication refills, and demographic update lag across EHR systems.

Solution: Referrals & Assessments Agent triages incoming referrals and routes to specialists. EHR Read-Write Agent manages medication refills and demographics via MuleSoft integrations with Epic, athenahealth, and Cerner.

MuleSoft's role: Bidirectional data exchange — reading and writing clinical notes, diagnoses, medications, and demographics into external EHRs. MuleSoft Omni Gateway sits inline to detect/filter PHI in transit and validate schemas.

🏦 Enterprise Supply Chain & Banking — MuleSoft Agent Fabric

Problem: Orchestrating order fulfillment and banking reconciliation across fragmented, multi-vendor agent ecosystems securely.

Solution: MuleSoft Agent Broker uses an LLM to autonomously decompose tasks and invoke the required MCP and A2A agents. In banking, the agent autonomously reconciles statements while Omni Gateway detects and redacts sensitive financial PII from logs in real time.

Paste these prompts into Claude Code or Cursor Agent mode after connecting your Salesforce org.

1
List my open Opportunities closing this quarter, grouped by Account Easy

Returns a table of active deals from your Salesforce org with account names, amounts, and close dates.

2
Show me all Contacts at [Account Name] with their email and last activity date Easy

Queries the Salesforce Contact object using SOQL via the MCP soql_query tool.

3
Create a new Task for [Contact Name] with subject "Follow-up on proposal" due in 3 days Easy

Uses sobject-mutations to create a Task record linked to the contact in your Salesforce org.

4
Analyze my Health Cloud patient accounts — which ones have had no activity in 90+ days? Medium

Queries Health Cloud patient accounts and activity history to identify care gaps.

5
Using MuleSoft, create an API that reads patient data from Salesforce Health Cloud and maps it to FHIR R4 Patient format Advanced

Combines the Salesforce MCP (data read) with the MuleSoft MCP (flow generation + Exchange search) to scaffold a complete FHIR integration.

6
Search my Salesforce org metadata for all custom objects related to "Patient" or "Member" Medium

Uses mcp-provider-metadata to inspect your org's schema — useful for understanding what Health Cloud data structures exist before building integrations.

The MuleSoft + Salesforce combo: The most powerful prompts chain both MCP servers in a single agent session. The Salesforce MCP reads your org data; the MuleSoft MCP builds the integration that connects it to external systems. One agent, two platforms, zero custom code to start.
